# 第1章第2节：大语言模型基础回顾：从Transformer到ChatGPT，LLM的工作原理

#### 大家好，我是秋天。



这一节课，我们来补一块非常关键的基础知识：**大语言模型，也就是 LLM，到底是怎么工作的。**

为什么在 Agent 课程里，要专门回顾 LLM？

因为今天绝大多数 Agent 系统，底层都离不开大语言模型。你可以把它理解为：如果 Agent 是一个“会思考、会调用工具、会执行任务的智能体”，那么 LLM 就是这个智能体最核心的“大脑”。

很多同学在学习 Agent 的时候，容易直接进入框架、提示词、工作流、工具调用这些实操层面，但如果你对 LLM 的基本原理没有一个清晰认识，后面你会经常遇到几个问题：

- 为什么模型有时很聪明，有时又会犯低级错误？
- 为什么上下文一长，效果就会下降？
- 为什么提示词稍微一改，输出质量就变化很大？
- 为什么模型能“说得像懂了”，却不一定真的“做对了”？
- 为什么同样的 Agent 结构，换一个模型，效果差异会非常大？

这些问题，表面上看是 Agent 的问题，本质上往往是 **LLM 的能力边界问题**。

所以这一节课，我们不讲太多公式，也不做学术化展开，而是从实战视角出发，带大家建立一个够用、清晰、能支撑后续 Agent 学习的 LLM 认知框架。

这一节你会重点掌握四件事：

1. Transformer 为什么会成为大语言模型的基础
2. 大语言模型本质上是如何“理解”和“生成”语言的
3. 从 GPT 到 ChatGPT，中间到底发生了什么关键变化
4. 为什么 LLM 天然适合作为 Agent 的认知核心

---

## 一、先建立一个总认识：LLM并不是“真的理解了世界”

在正式讲 Transformer 之前，我们先要统一一个认知。

很多人第一次接触 ChatGPT，会觉得它像真的“理解”了你的问题，甚至像“有意识”一样在和你交流。但从技术角度讲，LLM 最底层做的事情其实非常朴素：

**根据上文，预测下一个最可能出现的词。**

是的，大语言模型最基本的训练目标，并不是“理解世界”，也不是“知道真相”，而是：

**给定一段上下文，预测接下来最可能出现什么。**

比如一句话：

> 今天天气很好，我想去\_\_\_\_

模型要预测下一个词，可能是“公园”“散步”“外面”等等。

你可能会说，这不就是“文字接龙”吗？

某种意义上，是的。但关键在于，当模型的参数足够大、训练数据足够多、上下文足够长时，这种“预测下一个词”的能力，会涌现出非常强的语言理解、知识组织、逻辑表达和任务跟随能力。

也就是说：

**LLM 的强大，不是因为它被显式教会了所有任务，而是因为在海量语言数据中学会了语言背后的结构、模式和关联。**

这件事非常重要。因为它决定了我们后面如何看待模型的优点与缺点：

- 它擅长模式匹配和语言生成
- 它能压缩大量知识并进行调用
- 它可以表现出推理能力
- 但它的“理解”并不等于人类意义上的理解
- 它也可能一本正经地说错话，也就是我们常说的“幻觉”

所以，LLM 不是魔法，它本质上是一个规模极大的概率模型。只是这个概率模型，大到足以表现出接近通用智能的一部分能力。

## 二、为什么一切都要从Transformer讲起

### 1. Transformer 之前的问题是什么

在 Transformer 出现之前，处理自然语言的模型主要使用 RNN、LSTM 这类序列模型。

这类模型的问题在于，它们按顺序一个词一个词地处理信息。这样的好处是符合语言顺序，但坏处也很明显：

- 很难处理长距离依赖
- 训练效率低，难以并行
- 当文本很长时，前面的信息容易被“遗忘”

举个简单例子：

> 我昨天在会议上和产品经理讨论了三小时，最后我们决定把首页推荐逻辑全部重构，因为它在双十一期间暴露出了严重的问题……

如果模型读到后面，想理解“它”指的是什么，或者想把后面的结论和前面的背景关联起来，传统序列模型就会比较吃力。

所以，NLP 领域一直需要一种更强的架构，能够更高效地理解整段文本内部的关系。

### 2. Transformer 的核心突破

2017 年，Transformer 提出后，整个自然语言处理领域发生了根本性变化。

Transformer 最核心的突破，可以概括成一句话：

**它让模型能够在处理一个词时，同时关注整段上下文里与它最相关的其他词。**

这个能力，就是著名的 **Attention，注意力机制**。

你可以把它理解成：当模型读到一句话中的某个词时，它不会只机械地按顺序往后读，而是会动态判断：

- 这句话里哪些词和当前词关系最强？
- 哪些信息更值得重点关注？
- 哪些位置虽然离得远，但其实语义上很关键？

这就像人读文章时，不是平均地看待每个字，而是会自动抓住重点和关联。

### 3. Self-Attention 是什么

Transformer 里面最核心的机制就是 **Self-Attention，自注意力**。

所谓“自注意力”，就是一句话中的每个词，在表示自己时，都会参考这句话里的其他词。

比如一句话：

> The animal didn’t cross the street because it was too tired.

这里的 “it” 指的是谁？是 animal，不是 street。

模型如果想理解 “it”，就必须去看前面哪些词和它关系更大。Self-Attention 做的，就是这种“动态建立关联”的事情。

它的价值在于：

- 能更好地处理上下文依赖
- 能更灵活地捕捉语义关系
- 可以并行计算，训练效率更高
- 非常适合大规模扩展

### 4. 多头注意力可以理解成“多角度看问题”

Transformer 里面还有一个重要设计，叫 **Multi-Head Attention，多头注意力**。

你可以把它简单理解为：模型不是只从一个角度去看词和词之间的关系，而是会从多个不同的角度同时观察。

有的头更关注语法关系，有的头更关注主谓宾，有的头更关注指代关系，有的头更关注长距离依赖。

最后再把这些不同角度的信息综合起来，形成更丰富的语义表示。

这也是为什么 Transformer 的表达能力会明显强于很多早期模型。

---

## 三、Transformer解决了什么，为什么它能支撑LLM时代

Transformer 之所以重要，不只是因为它效果更好，而是因为它第一次真正满足了“大模型时代”的几个核心条件：

### 1. 可扩展

模型可以做得更大，参数可以不断增加，训练数据可以不断增加。

### 2. 可并行

相比传统序列模型，Transformer 更适合现代 GPU/TPU 的并行训练方式，这意味着它可以在工程上被真正做大。

### 3. 长文本建模能力更强

虽然长上下文仍然有成本和限制，但相较于更早的模型，Transformer 已经大幅提升了对上下文关系的处理能力。

### 4. 具备统一建模能力

它不只是能做分类、翻译、摘要这些单点任务，而是为“通用语言建模”提供了统一底座。

正因为这几个特性，Transformer 才成为后来 GPT、BERT、ChatGPT 这些模型的共同基础。

所以你可以记住一句话：

**没有 Transformer，就没有今天的大语言模型浪潮。**

---

## 四、从BERT到GPT：两条重要路线

大模型的发展，并不是一开始就只有 GPT 一条路。在 Transformer 之后，业界大致出现了两类非常重要的路线。

### 1. BERT 路线：更偏“理解”

BERT 的训练方式，强调从上下文中理解词语含义。它擅长做的是：

- 文本分类
- 情感分析
- 信息抽取
- 问答匹配
- 命名实体识别

你可以把 BERT 看成更像一个“阅读理解型选手”。

它很擅长理解一句话是什么意思，但不一定擅长持续生成长文本。

### 2. GPT 路线：更偏“生成”

GPT 这一路线则更强调 **自回归生成**，也就是根据前文不断往后预测。

它擅长做的是：

- 长文本生成
- 对话
- 写作
- 代码生成
- 多轮任务跟随

你可以把 GPT 看成更像一个“续写型选手”。

而 Agent 为什么更依赖 GPT 这一路线？因为 Agent 的很多任务，本质上都需要连续生成：

- 生成计划
- 生成行动步骤
- 生成工具调用参数
- 生成观察结果总结
- 生成下一步决策

所以在 Agent 时代，**生成式模型**比纯理解式模型更容易成为核心引擎。

## 五、大语言模型到底是怎么“学会语言”的

### 1. 训练数据从哪里来

一个大语言模型，通常会在海量文本上进行预训练，这些文本可能来自：

- 网页
- 书籍
- 论文
- 代码
- 问答数据
- 技术文档
- 论坛内容

模型在训练时，并不是有人逐条教它“这句话是什么意思”，而是让它在大量文本中不断做同一件事：

**根据前文，预测后文。**

比如给模型一句话的前半段：

> Agent 的核心能力包括感知、决策和\_\_\_\_

模型需要预测下一个词，可能是“行动”。

通过无数次这样的训练，模型会逐渐学到：

- 词和词如何组合
- 句子如何组织
- 概念之间如何关联
- 不同知识通常以什么形式出现
- 某类问题通常对应怎样的回答结构

### 2. Token 是什么

这里要补一个重要概念：**Token**。

模型并不是按“字”或者“词”来理解语言，而是按 token 来处理。Token 可以是一个字、一个词、词的一部分，甚至是标点符号。

所以当我们说“上下文长度”时，本质上是在说：

**模型一次最多能处理多少 token。**

这个概念很重要，因为它直接关系到 Agent 的能力边界：

- 上下文太长，成本就会升高
- 关键信息被稀释，模型效果可能下降
- 记忆、检索、摘要这些机制，很多时候都是为了节省 token 和提升有效上下文密度

### 3. 参数是什么

另一个常见概念是“参数量”。

参数可以理解为模型在训练过程中学到的内部权重，它们不是人类可直接阅读的知识条目，而是模型对语言模式和知识关系的一种压缩存储方式。

参数越多，不一定绝对越强，但通常意味着模型有更大的容量去学习更复杂的模式。

所以，大模型之所以“大”，并不只是模型文件更大，而是它拥有更强的表示能力和更高的知识压缩能力。

---

## 六、为什么GPT-3之后，世界突然觉得“模型变聪明了”

GPT-3 是一个非常关键的里程碑。

因为它让很多人第一次明显感受到：当模型规模提升到一定程度之后，会出现一些过去不明显的新能力，也就是我们常说的 **能力涌现**。

比如：

- 更强的上下文学习能力
- 更好的任务泛化能力
- 更自然的文本生成能力
- 更像样的多步推理表现
- 在没有专门训练某个任务的情况下，也能通过提示完成任务

这带来了一个非常重要的变化：

**模型开始从“针对单任务训练的工具”，变成“通过提示即可执行多种任务的通用接口”。**

这件事，为 Agent 铺平了道路。

因为 Agent 需要的，不是一个只能做单一任务的模型，而是一个可以在不同场景里快速切换角色、理解目标、执行步骤的通用认知核心。

---

## 七、从GPT到ChatGPT，中间到底多了什么

很多人会以为 ChatGPT 只是 GPT 模型做成了聊天界面。其实不是。

从 GPT 到 ChatGPT，中间至少发生了三类关键变化。

### 1. 指令跟随能力增强

早期语言模型更像“续写机器”，你给它一段话，它会继续往下写。但用户真正需要的不是续写，而是：

- 回答我的问题
- 按我的要求输出
- 遵守指定格式
- 执行明确任务

所以后来模型会经过专门的 **指令微调**，让它更擅长理解“你要我做什么”。

这一步非常关键。因为 Agent 的本质，就是接收目标并执行任务。如果模型连指令都跟不稳，就谈不上做 Agent。

### 2. 对话能力增强

ChatGPT 之所以让用户体验大幅提升，是因为它不再只看单轮输入，而是能在多轮对话中保持上下文连续性。

这意味着模型开始更像一个“交互系统”，而不是一次性生成器。

对 Agent 来说，这同样非常重要。因为很多任务都不是一轮完成的，而是：

- 用户提出需求
- 模型澄清目标
- 模型生成方案
- 调用工具
- 返回结果
- 根据反馈再修正

所以，多轮对话能力本质上是在为 Agent 的任务闭环提供基础。

### 3. 人类偏好对齐

另一个关键变化，是模型不再只追求“语言上最像训练数据”，而是开始对齐“人类觉得有帮助、清晰、安全、符合预期”的输出方式。

这类优化让模型输出更稳定、更有礼貌、更贴近用户意图。

这也是为什么 ChatGPT 相比原始 GPT，会显得更“像助手”。

从 Agent 的视角看，这一步的意义在于：

**模型不只是会生成内容，还开始更像一个能协作、能服从任务目标的执行者。**

## 八、ChatGPT看起来像在思考，它到底在做什么

这是很多课程里最容易讲得神秘的一部分。但我们这里尽量讲清楚，不神化。

当你问 ChatGPT 一个问题时，它大致在做几件事：

### 1. 把你的输入编码成 token

模型先把你的问题拆成 token，转换成向量表示。

### 2. 通过多层 Transformer 处理上下文关系

每一层都会不断更新各个 token 的表示，让模型逐渐理解：

- 当前问题的主题是什么
- 关键词之间是什么关系
- 用户可能想完成什么任务
- 输出应该采用什么风格和结构

### 3. 逐步预测下一个 token

模型不是一次性生成完整答案，而是一个 token 一个 token 地往后生成。

每生成一步，新的输出又会变成下一步的输入。于是模型就在这个循环中，一点一点把整段回答生成出来。

### 4. 采样策略会影响输出风格

模型并不是永远只选概率最高的那个词。有时会根据温度、采样策略等机制，在多个高概率候选里选择不同结果。

这就是为什么同一个问题，模型有时回答略有不同。

这也说明一个本质问题：

**模型输出不是“检索出唯一正确答案”，而是在概率空间里生成一个相对合理的回答。**

所以它有创造性，也有不确定性。

## 九、LLM为什么天然适合作为Agent的大脑

学到这里，我们就可以把重点收回来：为什么 LLM 会成为 Agent 时代的核心基础设施？

因为它刚好具备 Agent 所需要的几种关键能力。

### 1. 它能理解自然语言目标

用户不会用状态机语言给 Agent 下命令，而是会直接说：

- 帮我总结这份报告
- 帮我写一封邮件
- 帮我分析这段代码
- 帮我调用 API 完成这个流程

LLM 天然擅长理解这种自然语言目标。

### 2. 它能把复杂任务拆成步骤

很多任务不是一步完成的。模型可以先生成计划，再逐步执行。

这就使它非常适合作为任务编排的核心。

### 3. 它有通用知识和迁移能力

LLM 不需要为每个小任务单独训练一次。它可以把已有知识迁移到新任务中。

这使 Agent 具备了前所未有的通用性。

### 4. 它可以通过工具扩展能力边界

模型本身不能直接查实时数据、不能直接操作系统、不能直接发请求。但一旦接入工具，它就能把“语言能力”转化成“行动能力”。

这就是 Agent 最关键的一步：**从会说，变成会做。**

### 5. 它适合作为统一接口层

过去不同系统之间的交互，需要写大量固定规则和流程。而今天，LLM 可以作为一个统一的语义接口，把人类意图翻译成机器动作。

这也是为什么大家会说：LLM 让软件第一次真正具备了“按意图编程”的可能性。

## 十、但我们也必须清楚：LLM不是万能的

做付费课程，不能只讲模型有多强，也要把边界讲清楚。

LLM 的主要局限包括：

### 1. 它可能产生幻觉

也就是看起来很自信，但其实说错了。

### 2. 它不天然可靠

同一个问题，多次输出可能不同。所以如果任务要求强确定性，就必须加约束、加校验、加工具验证。

### 3. 它的记忆受上下文限制

模型不是无限记忆的。上下文窗口再长，也依然有限，而且越长不代表越稳定。

### 4. 它不直接等于行动系统

模型本身只会生成 token，真正的执行还需要外部系统配合。

### 5. 它的推理能力并不总是稳定

有些题它会做，有些类似题它又可能做错。所以不要把“模型偶尔表现出的高水平推理”误认为“稳定可靠的逻辑引擎”。

这也是为什么在 Agent 系统设计里，我们通常不会只信模型本身，而是会搭配：

- 工具调用
- 工作流约束
- 外部记忆
- 结果校验
- 人在回路机制

---

## 十一、你真正需要掌握的，不是公式，而是LLM的工程视角

如果你是做 Agent、做 AI 应用，关于 LLM，最重要的不是把底层数学全背下来，而是建立工程上的正确理解。

你至少要知道这几件事：

### 1. LLM 是概率生成模型，不是真理机器

所以输出要验证，不要盲信。

### 2. LLM 擅长语义理解和文本生成

所以它适合做任务理解、规划、总结、转换和沟通。

### 3. LLM 不擅长强确定性计算和真实世界直接执行

所以要接工具、接系统、接校验链路。

### 4. 提示词本质上是在塑造上下文

你给模型什么信息，决定了它如何理解任务。

### 5. Agent 的上限，往往取决于模型能力与系统设计共同作用

不是模型强就一定做得好，也不是工作流复杂就一定效果好。

这几条认知，后面你在做 Agent 产品设计时会非常有用。

## 十二、本节小结

这一节课，我们从 Transformer 一路讲到 ChatGPT，核心是希望大家建立一个足够扎实的 LLM 基础认知。

可以把今天的重点总结成这样几句话：

- **Transformer** 解决了长距离依赖和并行训练问题，成为大模型时代的基础架构
- **LLM** 的核心训练方式，是根据上下文预测下一个 token
- **GPT 路线** 更适合生成式任务，因此更容易成为 Agent 的核心模型
