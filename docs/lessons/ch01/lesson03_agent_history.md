# 第1章第3节：Agent的发展历程：从符号主义到LLM驱动的Agent

大家好，我是秋天。

这一节课，我们来系统梳理一下 Agent 的发展历程。

很多同学一听到 Agent，会觉得这是一个非常新的概念，似乎是大模型时代才突然出现的。其实并不是。Agent 背后的核心思想——也就是“让机器能够感知环境、做出决策，并采取行动来完成目标”——已经贯穿了整个人工智能发展史。

所以，如果我们想真正理解今天的 LLM Agent 是怎么来的，就不能只看 ChatGPT 之后的变化，而是要把视角拉长，从符号主义开始，一路看到今天的大模型驱动阶段。

这节课我会带大家用一条清晰的主线来理解 Agent 的演化。你会看到，不同阶段的技术范式虽然差异很大，但它们其实都在回答同一个问题：

**如何让机器从“被动执行命令”，走向“主动完成任务”。**

---

## 一、Agent发展的五个关键阶段

如果我们把 Agent 的发展历史浓缩一下，大致可以分成五个阶段：

1. **符号主义阶段**：强调知识表示、逻辑推理和规划。
2. **专家系统阶段**：强调把领域知识编码进去，让系统在特定场景中做决策。
3. **行为主义阶段**：强调智能不一定来自复杂推理，也可以来自对环境的实时响应。
4. **机器学习与强化学习阶段**：强调从数据和反馈中学习策略，而不是完全依赖人工编写规则。
5. **LLM驱动Agent阶段**：借助大语言模型的理解、推理和工具调用能力，让 Agent 具备更强的通用任务执行能力。

下面我们逐段来看。

---

## 二、符号主义：最早的“会思考的机器”

Agent 的早期思想，最早可以追溯到人工智能的符号主义时期。

### 1. 什么是符号主义？

符号主义认为，人类智能的本质可以通过**符号表示和逻辑推理**来实现。

简单来说，就是先把世界抽象成一套规则、事实和符号，再让机器按照这些规则进行推理，最终得出结论或执行计划。

这一时期的核心理念是：

**智能 = 知识表示 + 逻辑推理**

在这个阶段，Agent 更像一个“理性规划者”。它会先分析问题，再规划步骤，最后执行动作。

### 2. 代表性系统

#### Logic Theorist

1956 年，Newell 和 Simon 开发了 Logic Theorist，被认为是最早的 AI 程序之一。它能够证明数学定理。

这个系统的重要意义在于，它首次展示了机器可以通过符号推理来解决复杂问题。

#### GPS（General Problem Solver）

随后，他们又提出了 GPS，也就是“通用问题求解器”。

GPS 的目标很宏大：希望用统一的方式解决不同类型的问题。它采用“目标—手段分析”的思想，也就是不断比较当前状态和目标状态之间的差距，再选择合适的操作去缩小差距。

这其实已经非常接近今天 Agent 的核心逻辑了：

- 先有目标
- 再判断当前状态
- 然后规划行动路径

#### STRIPS

到了 1970 年代，STRIPS 进一步推动了规划系统的发展。

STRIPS 主要用于机器人规划，它能够定义：

- 当前世界状态是什么
- 可以执行哪些动作
- 每个动作的前提条件是什么
- 每个动作执行后会产生什么结果

这套思想影响非常深远。即使到了今天，我们在设计 Agent 的任务拆解、状态管理和行动链路时，仍然能看到 STRIPS 的影子。

### 3. 符号主义阶段的贡献与局限

符号主义最大的贡献，是首次系统化地提出了“智能体如何做决策”的框架。

它让我们知道，一个 Agent 不只是执行动作，还要具备：

- 对环境和问题的表示能力
- 对目标的建模能力
- 对行动路径的规划能力

但它的局限也很明显。

最大的问题在于：**现实世界太复杂，规则太难穷举。**

在封闭环境下，符号主义系统表现不错；但一旦进入开放、模糊、不确定的真实世界，靠人工编写规则就会迅速失效。

所以，接下来 AI 开始走向第二个阶段：专家系统。

---

## 三、专家系统：把专家经验写进机器里

### 1. 专家系统的基本思想

专家系统可以理解为符号主义在垂直领域的一次工程化落地。

它不再追求“通用智能”，而是聚焦在某个专业领域里，把专家的知识、经验和判断规则编码到系统中，让机器像专家一样做决策。

专家系统通常包含两个核心部分：

- **知识库**：存储专家规则和事实
- **推理机**：根据规则进行推导和判断

这时候的 Agent，已经开始具有一种“在特定任务中代替人决策”的味道了。

### 2. 代表性系统

#### MYCIN

MYCIN 是医学领域非常经典的专家系统。它能够根据病人的症状、化验结果等信息，辅助判断感染类型并推荐抗生素。

它的规则系统非常强大，在某些测试中甚至接近专家医生的水平。

#### XCON

XCON 是 DEC 公司用于计算机系统配置的专家系统。它可以根据客户需求自动生成硬件配置方案。

这个系统在工业界产生了巨大价值，也让人们看到了 AI 不只是学术研究，而是可以真正落地创造商业收益。

### 3. 专家系统阶段的启发

专家系统阶段对今天 Agent 的重要启发是：

**Agent 不一定要一开始就追求通用性，它可以先在特定场景中体现价值。**

这也是为什么今天我们看到很多企业 Agent，最先落地的不是“万能助手”，而是：

- 客服 Agent
- 销售 Agent
- 数据分析 Agent
- 编码 Agent
- 运维 Agent

它们其实都继承了专家系统的思想：

**先聚焦垂直任务，再逐步增强能力。**

### 4. 专家系统的瓶颈

不过，专家系统依然没有解决一个根本问题：

**知识获取成本太高。**

你必须不断采访专家、整理知识、写规则、维护规则。

而且一旦业务变化、环境变化、规则冲突，系统就会变得越来越难维护。这就是著名的“知识工程瓶颈”。

因此，AI 研究者开始反思：

智能是不是不一定来自复杂规则？

于是，行为主义登场了。

---

## 四、行为主义：智能未必来自推理，也可能来自行动

### 1. 行为主义的核心观点

行为主义对符号主义提出了非常强烈的挑战。

它认为，智能体不一定需要构建复杂的世界模型，也不一定要先推理再行动。

很多时候，**智能行为本身可以直接从感知—行动的闭环中涌现出来。**

换句话说：

**先行动，再在与环境的交互中体现智能。**

### 2. Rodney Brooks 与 Subsumption Architecture

行为主义最有代表性的人物之一是 Rodney Brooks。

他提出了非常著名的 **Subsumption Architecture（包容式架构）**。

这个架构强调：

- 不必先构建完整世界模型
- 不必中央统一规划
- 可以把系统拆成多个行为层
- 低层负责基础反应，高层负责更复杂目标
- 各层通过优先级和覆盖关系协同工作

比如一个机器人可以同时具备：

- 避障行为
- 漫游行为
- 寻找目标行为

当它运行时，不是先把整个世界“想明白”，而是在环境中不断感知并快速响应。

### 3. 行为主义对 Agent 的影响

今天我们为什么还要学行为主义？

因为它提醒我们一件非常重要的事：

**Agent 不只是“会想”，还必须“能动”。**

如果一个系统推理能力很强，但无法及时与环境交互，它依然不是一个强 Agent。

这一点在机器人、自动驾驶、游戏 AI 和实时决策系统中尤其重要。

而且，行为主义还启发了后来很多关于多模块协同、分层控制和反应式系统的设计思想。

### 4. 行为主义的不足

当然，行为主义也有问题。

如果系统只依赖局部反应，没有全局规划能力，那么面对长链路任务、抽象目标和复杂推理时，就会显得能力不足。

所以，后来的研究开始尝试把“推理能力”和“反应能力”结合起来。

在这个过程中，多 Agent 系统开始发展起来。

---

## 五、多Agent系统：从单个智能体到协作智能

### 1. 为什么会出现多Agent系统？

随着问题复杂度提升，人们发现很多任务并不适合由一个单一 Agent 独立完成。

因为真实世界中的任务常常具备这些特征：

- 分布式
- 多角色参与
- 信息不完全
- 需要协作与协调

于是，多 Agent 系统，也就是 Multi-Agent Systems，开始成为一个重要研究方向。

### 2. 多Agent系统关注什么？

多 Agent 系统研究的问题包括：

- 多个 Agent 如何通信
- 如何分工
- 如何协商
- 如何竞争与合作
- 如何在局部信息下形成整体行为

这类研究在机器人集群、交通调度、供应链优化、博弈系统中都有广泛应用。

### 3. 对今天的启发

今天很多 LLM Agent 框架喜欢设计多个角色，例如：

- Planner：负责规划
- Executor：负责执行
- Critic：负责审查
- Researcher：负责信息检索

你会发现，这种思路和早期多 Agent 系统其实非常接近。

区别在于，过去的多 Agent 更强调规则和协议，而今天的多 Agent 往往借助大模型来承担角色理解、任务分配和自然语言交互。

也就是说，**多 Agent 的组织思想很早就有了，只是今天被 LLM 放大了能力边界。**

---

## 六、机器学习与强化学习：让Agent从经验中学习

### 1. 从“写规则”到“学策略”

如果说前面的阶段主要依赖人工设计知识和行为，那么机器学习阶段最重要的转变就是：

**不再主要依赖人手写规则，而是让系统从数据中学习。**

在这个阶段，Agent 的核心问题开始变成：

- 如何感知环境状态
- 如何根据经验选择动作
- 如何根据反馈优化策略

这就把 Agent 推向了一个更加动态的方向。

### 2. 强化学习的意义

强化学习尤其适合 Agent 场景，因为它天然描述的就是一个智能体与环境交互的过程：

- Agent 观察状态
- 采取动作
- 环境返回奖励
- Agent 调整策略

这和我们今天理解 Agent 的方式几乎是完全一致的。

所以，从某种意义上说，强化学习是最“正统”的 Agent 学习范式之一。

### 3. 代表性成果

#### Deep Q-Network（DQN）

DQN 的意义在于，把深度学习和强化学习结合起来，让系统可以直接从高维输入中学习决策策略。

这标志着 Agent 不再只是在简化环境里做决策，而是开始能处理更复杂的感知输入。

#### AlphaGo

AlphaGo 的出现，是强化学习与搜索结合的标志性事件。

它不仅让世界看到了机器在复杂博弈任务中的决策能力，也让更多人意识到：

**智能体可以通过学习和搜索的结合，在复杂环境中做出高质量行动。**

### 4. 机器学习阶段的局限

虽然强化学习很强，但它也有明显限制：

- 训练成本高
- 对环境反馈依赖强
- 泛化能力有限
- 很难直接处理开放世界的通用任务

比如，让一个强化学习系统去“帮我写一份商业分析报告”或者“调用多个工具完成一次市场调研”，这就不是它擅长的事情了。

于是，Agent 还需要一种新的能力：

**理解自然语言、处理开放任务、在复杂语义空间中进行推理。**

这就把我们带到了今天最重要的阶段：LLM 驱动的 Agent。

---

## 七、LLM驱动Agent：Agent真正走向通用化

### 1. 为什么大模型改变了Agent？

在大模型出现之前，很多 Agent 系统都有一个共同难题：

**缺少通用认知引擎。**

要么规则写死，要么策略局限于特定环境，要么系统只能处理结构化问题。

而大语言模型的出现，第一次让机器具备了较强的：

- 自然语言理解能力
- 通用知识调用能力
- 任务分解能力
- 多步推理能力
- 生成与交互能力

这意味着，Agent 不再只是“某个固定场景下的自动决策器”，而开始变成“能够理解任务、规划步骤、调用工具、执行流程的通用智能体”。

### 2. 关键技术演进

#### Transformer

Transformer 架构的提出，为后来的大模型奠定了基础。它使模型能够更高效地处理长距离依赖和大规模语料。

#### BERT、GPT-3、ChatGPT

从 BERT 到 GPT-3，再到 ChatGPT，大模型逐步展现出惊人的语言理解和生成能力。

尤其是 ChatGPT，让更多人第一次直观感受到：

机器不仅能回答问题，还能进行多轮交互、理解任务意图、辅助完成复杂工作。

这使得 Agent 从研究概念迅速走向产品实践。

### 3. LLM Agent 的核心能力结构

一个典型的 LLM Agent，通常包括这样几个能力模块：

- **感知输入**：理解用户指令、上下文和环境信息
- **推理与规划**：分解任务、生成步骤、判断优先级
- **记忆机制**：保存短期上下文和长期信息
- **工具调用**：访问搜索、代码、数据库、API 等外部能力
- **行动执行**：根据计划逐步操作，直到完成目标
- **结果反思**：检查输出质量，必要时修正路径

你会发现，这其实把过去几十年 Agent 研究中的很多思想重新整合了一遍：

- 符号主义提供了推理和规划的思想
- 行为主义强调感知—行动闭环
- 多 Agent 提供了协作组织方式
- 强化学习强调与环境交互和策略优化
- 而 LLM 则提供了一个通用认知核心

### 4. ReAct：Reasoning + Acting

在 LLM Agent 发展过程中，一个非常重要的框架是 **ReAct**。

ReAct 的思想很简单，但非常关键：

**让模型一边推理，一边行动。**

也就是说，模型不是一次性把答案想完，而是在思考过程中不断调用外部工具、观察返回结果，再继续思考下一步。

这就把“语言智能”和“环境交互”真正连接起来了。

这也是为什么很多人会把 ReAct 看成现代 Agent 框架的重要起点之一。

### 5. Tool Use / Function Calling

如果说 ReAct 让 Agent 学会了“边想边做”，那么 Tool Use 或 Function Calling，则让 Agent 真正具备了“连接外部世界”的能力。

比如：

- 调用搜索引擎查资料
- 调用数据库查询信息
- 调用代码解释器运行程序
- 调用办公系统创建文档
- 调用业务 API 完成流程操作

这时，大模型不再只是聊天机器人，而开始变成一个任务执行中枢。

### 6. Agent框架的兴起

随着实践增多，围绕 LLM Agent 的框架也迅速发展起来，例如：

- **AutoGPT**：让 Agent 自动循环执行目标
- **AutoGen**：强调多智能体对话协作
- **CrewAI**：强调角色分工和团队式协作
- **LangGraph**：强调状态流转、节点编排和可控执行

这些框架虽然设计方式不同，但都在尝试解决同一个问题：

**如何让大模型稳定、可控、可扩展地完成真实任务。**

## 八、从历史回看今天：Agent到底进化了什么？

如果我们站在今天回看整个历史，会发现 Agent 的演化并不是简单的“旧技术被新技术替代”，而更像是一个不断叠加的过程。

### 1. 没有哪个阶段是完全消失的

今天的 Agent 系统里，仍然能看到过去各个时期的影子：

- 任务规划里有符号主义的思想
- 工作流编排里有专家系统和规则引擎的影子
- 实时交互里有行为主义的思路
- 策略优化里有强化学习的影响
- 多角色协同里有多 Agent 系统的框架

所以，LLM Agent 不是凭空诞生的，而是站在整个 AI 发展史上的一次整合与升级。

### 2. 真正的变化在于“通用认知核心”出现了

过去很多 Agent 方法不是没有价值，而是缺少一个足够强的中枢，无法把感知、推理、行动、记忆、协作统一起来。

LLM 的出现，第一次让这个中枢变得足够实用。

这就是为什么 2023 年之后，Agent 会突然爆发。

不是因为“Agent 这个概念”今天才出现，而是因为今天终于有了一种足够通用的能力，能把它真正做出来。

---

## 九、你应该如何理解今天的Agent

学到这里，我希望大家对 Agent 建立一个更扎实的理解：

**Agent 不是一个单一技术名词，而是一整套“让机器围绕目标持续感知、决策、行动”的思想体系。**

今天的大模型，只是让这套体系进入了一个全新的发展阶段。

所以，当你以后看到各种 Agent 产品、框架和概念时，不要只盯着“它用了哪个模型”，更要看它是否真正具备以下几个关键能力：

- 是否有明确目标
- 是否能理解环境
- 是否能规划步骤
- 是否能调用工具
- 是否能根据反馈调整行动
- 是否能持续完成任务而不是只回答一句话

如果这些能力具备了，它才更接近一个真正的 Agent。

---

## 十、本节小结

这节课我们梳理了 Agent 的发展历程，核心脉络可以概括为：

- **符号主义**：让机器学会表示知识和逻辑推理
- **专家系统**：让机器在特定领域像专家一样决策
- **行为主义**：强调与环境交互带来的智能行为
- **多Agent系统**：强调多个智能体之间的协作
- **机器学习与强化学习**：让 Agent 从经验和反馈中学习策略
- **LLM驱动Agent**：让 Agent 拥有通用语言理解、推理和工具使用能力

如果说过去几十年的发展是在不断补齐 Agent 的各个能力模块，那么大模型时代最大的变化，就是把这些模块第一次有机会整合成一个更通用、更实用的系统。
